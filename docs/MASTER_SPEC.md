# HYOOL 总纲

> Agent 每次开工只读本文件 + `FEATURES.md` 里对应条目的文件清单。不要通读仓库。

## 1. 项目定位

HYOOL = 幻想 × 无限 × 生命 × 彼岸（首页四入口）。

核心理念：让用户创造属于自己的作品。

**商业级底座（定案）**：之后通用引擎 / 编辑器底座、模板、`kind`、样品，一律按「小白填积木也能做出可上线作品」设计。对标可发布的互动小说 / 卡牌等商业形态，不接水果、躲避、打地鼠一类玩具小游戏。能力要够简单上手，成品要够直接上线。

**剧情 × 卡牌 × 关系 × 演出（定案 2026-08-26）**：作品不是「玩家跟 AI 自由聊推进剧情」。核心环是 **剧情系统 → 选项 → 玩家选择 → 状态变化 → 角色实时演出**。AI **不决定剧情结果**，只负责表现层（吐槽、临场台词、关系口吻）。详见 `docs/editor-vision.md`「三层模型」与 `docs/ARCHITECTURE.md`。

**分发与消费（定案 2026-08-26）**：
- **站内消费固定**：付费/解锁等消费发生在 HYOOL 站内，不按「导出独立游戏包再另卖」设计。
- **作品以网页模式分享**：可玩链接 / 广场 / 个人主页露出为主；播放器继续是站内 Web，不优先 ZIP、桌面 exe、多端安装包。
- **远景**：个人主页升级为「店」、生命侧升级为「市场」，远期可有对应 App；当前仍以 Web 把分享与播放链路做稳，App 不提前开分支。

栈：Cloudflare Workers + D1 + 静态资源（`public/`）。入口 `src/index.js`。

## 2. 当前阶段

优先完善：

- **彼岸**：账号、个人主页、我的彼岸（角色/世界）
- **幻想**：作品编辑器（互动小说 · 卡牌；商业可发布）

**无限**（图片/音频工具箱）、**生命**（生命世界/广场）先保留，非任务不要主动改。

## 3. 页面结构

首页 `public/index.html`（世界选择）

- 幻想 → `fantasy.html`（制作总览）→ **作品编辑器**（小说 / 卡牌）
- 彼岸 → `yonder.html` 登录后个人主页 / `hub.html` 我的彼岸
- 无限 → `workspace.html`（工具箱，非本次重点）
- 生命 → `/plaza` 幻灵世界广场、`world.html`（非本次重点）

## 4. 核心设计原则

- 黑色为主、极简、数字世界感
- 不要堆砌功能
- **不随意改变已经确定的视觉设计**
- 图片不上传服务器作「素材库」卖点时：工具类走本地 WASM；作品媒体走现有 `/api/upload` URL 引用
- **作品底座**：积木 / 样品 / 播放器必须通向「广场可发布、主页可露出、网页可分享」的成品；禁止再加幼儿园式小游戏模板或并行玩具工坊
- **分发**：Web 分享优先；独立包导出非当前目标（见「分发与消费」定案）
- **AI 不控剧情**：剧情分支与胜负/变量由程序与作者积木决定；LLM 只生成表现层台词（可关、可降级为预设），失败不得改写分支结果

## 5. 当前画布（作品）

用户自选：

- 横屏 1920 × 1080（实现里常用 16:9，标准档约 1280 宽）
- 竖屏 1080 × 1920（9:16）

字段：作品 `orientation`: `landscape` | `portrait`。

## 6. 开发原则

修改前：

1. 先在 `FEATURES.md` 找到文件，再打开
2. 先理解现有逻辑
3. 尽量局部修改
4. 不随意重构
5. 不删除已有功能
6. 改完检查同一数据/状态的相关页面

禁止推翻 `ARCHITECTURE.md` / 本文件已写明的架构决策；要改先问用户。
