## 解读（2026-08-24 对齐）

- **分层含义**：通用底层 = 引擎/平台能力（共用投资）；作品类型 = 产品形态（薄壳）。类型之间共享存储与底层系统，而非各写一套编辑器。
- **Project State 是地基**：若 stories 表的数据 JSON 演进为「类型无关」文档模型（scenes + timeline + 节点 + 资产引用），5 大类共享一套存储，每类只是不同的播放器/交互层。

## 现状对照（2026-08-24）

- **已实现**：叙事 → 互动小说 最小区间——`scene`/`dialogue` 两种积木、章节、横竖屏、播放；云端 stories 表 + `/api/stories` 全量接口 + 个人主页/广场展示。
- **底层可复用**：AI（Companion 层 / 世界引擎 / Director 层）、角色（角色库）、剧情（world 的 story timeline）。
- **未实现**：`choice` 分支积木、时间轴（一等维度）、素材库、音频、图片/动图积木（目前图片 base64 内嵌）、其余 4 大类 18 个类型。

## 硬约束（影响所有设计）

- **图片不上传服务器（隐私卖点，用户定案）** → 素材库只能「引用 URL + 本地缓存 + D1 只存结构/文本」。这直接决定素材库与数据模型设计。
