## 解读（2026-08-24 对齐）

- **分层含义**：通用底层 = 引擎/平台能力（共用投资）；作品类型 = 产品形态（薄壳）。类型之间共享存储与底层系统，而非各写一套编辑器。
- **Project State 是地基**：若 stories 表的数据 JSON 演进为「类型无关」文档模型（scenes + timeline + 节点 + 资产引用），5 大类共享一套存储，每类只是不同的播放器/交互层。
- **商业级底座（2026-08-25 定案）**：底层与类型壳都按「小白填表/积木 → 可上线成品」设计。参考样品、默认值、播放器要够新手用，产出要对标能挂主页/广场的互动小说与卡牌等，不做玩具小游戏线。
- **交互层 = 时间线积木拖排（2026-08-25）**：作品库三步创建；编辑中栏为竖向时间线（拖排序、文件拖上积木、对白/场景行内改）；底栏芯片加块；卡牌工作室表格式填空。不做节点连线画布。

## 三层模型（定案 2026-08-26）

卡牌 / 互动小说统一为：

**剧情驱动 × 卡牌战斗 × 角色关系 × 实时互动** — AI 只占很小一层。

```
剧情系统 → 给玩家选项 → 玩家选择 → 状态变化 → 角色实时演出
```

| 层 | 控制权 | 例子 | 禁区 |
|---|---|---|---|
| ① 游戏逻辑 | 程序 100% | HP、卡牌、印记、好感、战斗结果、变量 | LLM 不得写状态 |
| ② 剧情 | 作者 100% | 章节、场景、A/B/C、跳转、结局 | LLM 不得选分支、不得改结局 |
| ③ 表现 | 预设为主 + 可选 AI | 走路吐槽、战斗口令、「……谢谢你」 | 只改台词；失败用预设；不影响游戏结果 |

AI **只干三件事**（皆属表现层）：

1. **角色互动**：走路/待机时的吐槽反驳插嘴（优先预设事件 + 性格标签；很多内容不需要 LLM）
2. **小范围自由表达**：在「好感高 / 刚救人 / 场景危险」等**已由程序判定**的条件下，生成一句演出台词
3. **临场台词**：攻击失败、反击成功等战斗结果已定后，补一句配合感台词

原则：AI 今天聪明明天犯蠢，**游戏不崩**——模型/Token/API 波动只影响表现，不改剧情与胜负。  
体验目标：玩家感到「角色活着」，而不是「我在跟 AI 聊天」。  
HYOOL 核心理念保留：**AI 不是游戏本身，而是让作品活起来的工具**。

### 与现状的对应

- 已有：`choice` 跳转、卡牌战斗确定性结算、Companion「引擎落账 LLM 只演绎」、中枢 Blueprint 的 `logic` 预留
- 下一步优先补 **②**：~~剧情变量 + 选项条件/效果~~ ✅；**③**：~~表现事件 / 临场一句~~ ✅（`perf` + `/api/hub/live-line`）；~~分支可视 + 存读档 + visited~~ ✅
- 再往后：装备/时间轴一等维度、卡牌关系演出表扩写、中枢异步；**网页分享体验**（打开即玩、主页/广场露出）。独立 ZIP/多端包非当前目标（分发定案：站内消费 + Web 分享；远景店/市场 App）

## 现状对照（2026-08-26）

- **已实现**：互动小说（choice + **logic.state** + **perf 演出** + **分支图** + **播放存档** + **访问标记 v_***）；卡牌壳；女神挂机；剪映式时间线；Comfy；中枢前端；素材库。
- **底层可复用**：AI（Companion / 世界 / 中枢 / live-line）、角色库、剧情变量、素材库引用。
- **未实现（按三层推进）**：装备/时间轴一等维度/修仙完整壳/中枢异步——仍按商业级底座补。独立 ZIP **不做优先**（Web 分享定案）。

## 对标速览（吸收开源强项，不照搬引擎）

| | 强项 | HYOOL 取舍 |
|---|---|---|
| **GenStory** | AI 一句话出绘本/分支草稿，快 | 中枢只产骨架企划；**运行时 AI 不选分支**（三层模型） |
| **OpenWebGAL** | 成熟 VN 播放器、立绘转场、存读档、Terre 可视化、导出多端 | 学存读档与演出质感；不迁脚本引擎；云同步+广场是我们的差异 |
| **Tuesday.js** | 浏览器零安装、**流程图看分支**、场景拖放、JSON | 学分支可视化；坚持剪映式时间线，不做节点画布为默认 |
| **Kinexus** | **故事地图**（死端/孤儿）、条件选项+变量、visited、存读档、ZIP 导出 itch | 已对齐：分支图、条件/变量、访问标记、播放存档；ZIP **非路线**（我们走站内 Web 分享） |
| **HYOOL** | 云同步、彼岸社交、卡牌/挂机、三层定案、中枢+素材 URL 库；**站内消费 + 网页分享**；远景店/市场 App | 作者控剧情；程序控逻辑；AI 只表现 |

原则：吸收「可看见分支 / 可中途存档 / 可条件跳转」；拒绝「AI 写剧情结果」与整仓拷贝。

## 硬约束（影响所有设计）

- **图片不上传服务器（隐私卖点，用户定案）** → 素材库只能「引用 URL + 本地缓存 + D1 只存结构/文本」。这直接决定素材库与数据模型设计。
- **不上玩具线**：不恢复接水果 / 躲避 / 打地鼠等；新类型须能走**网页发布/分享**链路。
- **分发**：站内消费固定；作品网页分享；远景主页店 + 生命市场（App 后置）。
